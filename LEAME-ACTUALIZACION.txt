ACTUALIZACIÓN 3 — TEMA GENERAL Y PERMISOS DE EDICIÓN DEL CLIENTE

CORRECCIÓN DE PRESENTACIÓN
Se corrigió el alcance de los estilos: campos y botones ya no dependen del contenedor exclusivo de correos. La aplicación utiliza un tema Tailwind compartido en resources/css/tema.css y su archivo compilado public/css/tema.css.

Se retiró la carga de modulos.css y los estilos visuales independientes del editor de documentos. Se conservaron únicamente las reglas de geometría del lienzo y la hoja de impresión dentro del tema compartido. El archivo modulos.css queda como compatibilidad vacía para enlaces antiguos.

Componentes Blade reutilizables: ui.button, ui.field y ui.panel. Todos comparten bordes, color del negocio, altura de controles, espaciado, foco, estados deshabilitados y modo oscuro. Los íconos siguen usando el componente Blade x-icono del proyecto y tienen tamaño coherente dentro de los botones.

Formularios y pantallas revisados: movimientos de ingresos/gastos, listado y registro de correos, datos del negocio, usuarios del equipo, permisos, exportaciones, documentos, fotos, tarjetas, POS, galería de CV y portal del cliente. Los formularios nuevos aprovechan el ancho disponible y se adaptan a móvil. El diseño de impresión de CV, tarjetas y PDF conserva sus reglas de página.

PERMISOS PARA EDITAR CLIENTES
1. Para que un usuario del negocio edite fichas, active el permiso existente «Crear y editar clientes» desde Usuarios / Mi equipo. Este permiso sigue limitado a los clientes visibles para su negocio.
2. Para administrar qué puede editar el titular desde su cuenta personal, el administrador debe habilitar al encargado el permiso «Administrar edición del portal del cliente».
3. Entre a Clientes -> Ver ficha -> Cuenta y permisos del cliente.
4. Seleccione las secciones editables y guarde:
   - Datos personales, contacto y perfil.
   - País, documento de identidad y datos de nacimiento.
   - Foto del currículum y chat.
   - Estudios, experiencia, idiomas, habilidades y referencias.
5. Sin ninguna sección seleccionada, el portal queda en modo de consulta.

La misma configuración está disponible al editar una cuenta de tipo cliente desde Usuarios del administrador. Primero debe existir la cuenta personal. No se cambian contraseñas, cuentas ni roles para aplicar estos permisos.

Las cuentas anteriores que no tienen una selección explícita conservan la edición de toda su ficha propia. Los controles de las secciones restringidas se muestran deshabilitados; el servidor también rechaza envíos manuales de campos no autorizados. Se bloquea el cambio de foto por la ruta alternativa del chat cuando no está permitido. Las secciones protegidas no se borran al guardar otras. Las notas internas, roles, estado y permisos del sistema no son campos editables por el cliente.

La administración de acceso y permisos del portal corresponde al administrador general o al encargado autorizado del negocio. La eliminación de clientes está reservada al administrador general. Los permisos de ficha no sustituyen los controles de seguridad de la propia cuenta, como cambiar contraseña o verificar un correo personal.

INSTALACIÓN
1. Respaldar archivos y base de datos.
2. Copiar el código actualizado conservando .env y el almacenamiento existente.
3. Ejecutar: php artisan migrate --force
   Nueva migración: 2026_11_03_000002_edicion_portal_cliente.php
   Añade users.edicion_cliente como JSON nullable. No cambia los permisos anteriores por defecto.
4. Ejecutar: php artisan optimize:clear
5. Ejecutar: php artisan view:cache
6. Recargar el navegador con Ctrl+F5 para descartar estilos guardados.

El CSS compilado está incluido. Esta entrega no añade dependencias PHP o Node. Si todavía no instaló la actualización anterior, ejecute también npm ci para disponer de qrcode y mantenga las dependencias de PDF/imagen del proyecto.

Para recompilar el tema después de modificaciones propias: npm run css. La configuración de Tailwind ahora resuelve las rutas de contenido desde su propio archivo e incluye las clases utilizadas en los scripts de la aplicación.

ALCANCE
El ZIP contiene todo el código de la versión anterior y esta corrección. No contiene vendor, node_modules, .env, bases de datos, credenciales ni capturas internas de pruebas. GitHub y el servidor de producción no fueron modificados.

Se mantienen las funciones anteriores: negocios por tipo/país, libro auxiliar de ingresos y gastos opcionalmente vinculado al POS, exportaciones PDF/Excel, veinte diseños de CV con capturas y QR PNG de correos. El libro sigue siendo auxiliar y no contabilidad completa por partida doble. Los modelos avanzados de quitar fondo siguen requiriendo instalación local y validación de recursos; esta entrega no descarga modelos nuevos.
